# 2단계 — 로컬 ERD 편집기

선행 조건: [1단계](./01-foundation-and-domain.md) 완료. [공통 아키텍처](./00-scope-and-architecture.md)를 함께 적용한다.

## 목표와 범위

서버 저장 없이도 하나의 ERD를 실제로 설계할 수 있는 React 편집기를 만든다. 데이터 모델은 1단계의 공통 모델을 사용하고, React Flow의 nodes/edges는 렌더링용으로만 생성한다. 이 단계에서는 외부 ERD 파일 입출력, SQL 입출력, 프로젝트 공유를 구현하지 않는다.

## 화면과 사용자 흐름

- 상단: 문서 이름, 현재 SQL 대상·버전, 저장 상태, undo/redo.
- 왼쪽: namespace·테이블·뷰 목록과 이름 검색.
- 중앙: 테이블 노드·관계선·그룹·메모를 표시하는 캔버스.
- 오른쪽: 선택한 테이블·컬럼·제약·인덱스·관계의 속성 편집.
- 새 문서 만들기 → 테이블 추가 → 컬럼 추가 → 키 지정 → 관계 생성 → 다른 뷰에 같은 테이블 배치 순서로 사용할 수 있어야 한다.
- SQL target은 문서 생성 시 registry에 등록된 대상으로 정한다. 생성 후 단순 드롭다운 변경으로 DBMS 변환을 실행하지 않는다.

## 구현 작업

### 1. 문서 상태와 변경 명령

- `document`, 선택 상태, 포커스, 열린 패널, 뷰포트, 검증 진단을 분리한다. 선택·포커스 같은 임시 상태를 catalog에 저장하지 않는다.
- 테이블·컬럼·키 생성/수정/삭제, 뷰 배치, 관계 생성 등을 명령을 통해 수행한다. UI가 참조 객체를 제각각 직접 수정하지 않도록 한다.
- 하나의 사용자 작업을 undo/redo 한 단위로 묶는다. 드래그 중의 모든 포인터 이동을 별도 이력으로 저장하지 않는다.
- 새 명령을 실행하면 redo 분기를 제거한다. 명령 이력에는 문서 ID를 포함해 다른 문서로 섞이지 않게 한다.
- 입력 폼의 임시 문자열과 커밋한 값을 구분한다. 불완전한 이름 입력 때문에 캔버스 조작 전체가 중단되면 안 된다.

### 2. 테이블·컬럼·키 편집

- 물리명·논리명·설명, namespace, 컬럼 순서·자료형·nullable·default를 편집한다.
- PostgreSQL 타입 항목과 버전별 옵션은 dialect 메타데이터로 제공한다. 공통 폼에 PostgreSQL 타입명을 하드코딩하지 않는다.
- PK·UNIQUE·CHECK·일반/고유 인덱스를 독립 객체로 편집한다. 복합키의 컬럼 순서를 바꿀 수 있어야 한다.
- 타입·표현식 입력은 구조화된 필드와 SQL 식을 구분한다. IDENTITY·ENUM·SEQUENCE 같은 고급 속성은 capability에 따라 전용 설정을 제공하거나 명확히 미지원으로 표시한다.
- ENUM·SEQUENCE의 상세 폼은 4단계에서 완성해도 되지만, 불러온 모델을 이 단계의 편집기가 지우거나 단순 문자열로 축소하면 안 된다.
- 빈 이름·중복 물리명 등 의미 오류는 객체 위치와 함께 표시한다. 의미 오류가 있는 작성 중 문서도 임시 저장할 수 있다.

### 3. FK와 논리 관계

- 컬럼 연결점에서 드래그하면 FK 생성 대화상자를 연다. 참조하는 키와 대응 컬럼 목록을 확인한 뒤 생성한다.
- 복합 FK, 자기 참조, 서로를 참조하는 테이블을 지원한다. 데이터 타입 호환성과 키 유일성은 dialect 검증에 위임한다.
- 참조 동작 `ON DELETE`·`ON UPDATE`를 capability에 맞게 선택한다.
- FK 선은 constraint의 ID를 참조한다. 선과 FK 정의를 별개 원본으로 만들어 불일치시키지 않는다.
- FK의 nullable·unique 정보로 도출 가능한 cardinality만 표시한다. 부모가 반드시 자식을 가져야 한다는 논리 조건을 FK만으로 추측하지 않는다.
- 별도 논리 관계를 만들 수 있게 하되 실제 FK와 스타일·속성으로 구별한다. 논리 선을 SQL에 포함하지 않는다.

### 4. 캔버스와 뷰

- 이동·줌·fit view·미니맵·다중 선택·그리드 정렬을 제공한다.
- 논리명/물리명 표시 전환과 컬럼 접기를 제공한다. 표시 전환은 이름 자체를 변경하지 않는다.
- 뷰를 생성·복제·이름 변경·삭제하고, 기존 테이블을 다른 뷰에 추가할 수 있어야 한다.
- 뷰에서 제거와 실제 테이블 삭제를 다른 동작으로 제공한다. 실제 삭제 시 참조 FK·인덱스·모든 뷰의 영향을 미리 보여준다.
- 컬럼 삭제도 참조하는 키·FK·식의 영향을 처리한다. 삭제가 깨진 참조를 만들면 명령 전체를 거부하거나 명시한 의존 객체와 함께 원자적으로 삭제한다.
- 이름 변경이 SQL 표현식에 영향을 주는 경우 dialect의 안전한 재작성 결과를 사용한다. 아직 재작성할 수 없으면 해당 표현식을 검토 필요로 표시하고 향후 export를 차단한다.
- 메모와 테이블 그룹을 지원한다. 임의 HTML은 렌더링하지 않는다.

### 5. 브라우저 임시 복구

- IndexedDB에 문서 ID·임시 사용자 구분·변경 시각·형식 버전·기준 서버 revision을 포함한 복구 데이터를 저장한다. 서버 연결 전에는 기준 revision이 없다.
- 동일 브라우저에서 새로고침 후 임시 문서를 복구할 수 있게 한다. SQL 또는 JSON 파일 가져오기 기능으로 대체하지 않는다.
- 파일 다운로드가 아닌 브라우저 복구 기능임을 구분한다. 저장 공간 부족·복구 실패를 상태로 알려준다.
- 여러 탭에서 같은 로컬 문서를 열면 탭 구분과 알림을 제공하고 임시 복구본을 무조건 덮어쓰지 않는다.
- 3단계 로그인 도입 후 익명 임시 문서를 다른 계정에 자동 연결하지 않도록 복구 저장소의 소유 구분을 미리 둔다.

## 산출물

- React Flow 테이블·관계 렌더러와 도메인→화면 projection.
- 명령 기반 편집·undo/redo·참조 정리.
- 뷰·그룹·메모·검색·속성 패널.
- 브라우저 임시 저장·복구와 오류 안내.

## 검증

1. 샘플을 실제 편집해 테이블·컬럼·복합키·FK를 만들고 undo/redo로 정확히 되돌린다.
2. 테이블 이름 변경 후 FK 참조가 유지되고, 두 뷰의 표시가 함께 갱신된다.
3. 뷰에서 테이블을 숨겨도 catalog와 다른 뷰의 테이블이 남는다.
4. 컬럼 삭제·테이블 삭제 후 깨진 내부 참조가 남지 않는다.
5. 자기 참조·복합 FK를 생성하고 컬럼 순서·키 대응을 확인한다.
6. 새로고침·복구 실패·다른 탭 편집 시 사용자의 변경을 잃지 않는다.
7. 사용자 흐름 E2E는 생성→관계→undo→새로고침 복구 같은 핵심 동작에 집중한다. 화면 내부 배열 구조를 그대로 재검사하는 테스트는 만들지 않는다.

## 완료 기준

- [ ] 로컬에서 테이블·컬럼·키·관계를 실제 설계할 수 있다.
- [ ] 스키마 원본과 화면 정보가 분리되어 있으며 React Flow 데이터가 저장 원본이 아니다.
- [ ] 여러 뷰에서 같은 테이블을 재사용한다.
- [ ] 삭제·이름 변경·undo/redo가 참조 무결성을 유지한다.
- [ ] 새로고침 후 임시 작업을 복구할 수 있다.
- [ ] SQL 미구현 기능이 성공처럼 표시되지 않는다.
