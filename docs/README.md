# ERD 도구 단계별 구현 계획

작성일: 2026-11-18

이 문서 묶음은 단계별 구현 명세다. 현재 실행 방법은 [저장소 README](../README.md)에서 확인할 수 있다. 단계별 구현 기록과 검증 상태는 각 단계 문서에 기록한다.

## 확정된 요구사항과 설계 기준

- 웹에서 ERD를 생성·편집·저장·관리한다.
- PostgreSQL DDL import/export를 우선 제공한다.
- SQL 처리는 DBMS별 모듈을 추가해 확장할 수 있게 설계한다.
- eXERD·ERDCloud 등 외부 도구의 ERD 파일 import/export는 제외한다.
- 개발 언어는 프론트엔드와 백엔드 모두 TypeScript로 한다. React는 프론트엔드 UI 라이브러리로 사용한다.
- React Flow 기반 편집기, Node.js API, PostgreSQL 저장소를 기본안으로 한다.
- 실시간 공동 편집, DB 직접 접속·DDL 실행, 변경분 마이그레이션 SQL, DBMS 간 자동 SQL 변환은 초기 범위에 포함하지 않는다.
- 자체 JSON 백업 파일 입출력도 기본 구현 단계에서는 제외한다. 서버 저장·복원과 이미지 출력은 제공한다.

인증 방식, 라이브러리 구성 등 세부 선택은 구현을 시작할 수 있게 정한 기본안이다. 기존 환경과 충돌하면 근거와 변경 사항을 기록하고 조정하되, 사용자가 확정한 기능 범위를 임의로 늘리지 않는다.

1~7단계가 PostgreSQL MVP다. 8단계는 PostgreSQL 구문·버전을 넓히거나 추가 DBMS를 실제 지원할 때 실행한다. 확장 대상이 아직 정해지지 않았다면 8단계는 착수하지 않아도 된다. 확장 계약과 패키지 경계는 1단계부터 구현한다.

## 단계별 개발 요청 방법

예시:

> docs/README.md와 docs/00-scope-and-architecture.md를 읽고, docs/01-foundation-and-domain.md에 따라 1단계를 구현해줘. 선행 조건을 확인하고 이 단계의 완료 기준까지 검증해줘.

후속 단계 요청에서도 해당 단계 문서와 공통 문서를 함께 읽는다. 구현자는 다음 순서로 진행한다.

1. 현재 코드와 선행 단계의 실제 완료 여부를 확인한다.
2. 선행 단계가 일부 빠졌으면 해당 단계에 필요한 최소 작업을 먼저 보완하고 보고한다.
3. 지정 단계의 범위를 구현한다. 후속 단계의 실제 기능을 미리 완성하려고 범위를 확대하지 않는다.
4. 명시된 검증과 기존 기능에 필요한 회귀 검증을 수행한다.
5. 변경 파일, 실행 방법, 수행한 검사, 남은 제한을 보고한다.
6. 실제 완료한 항목만 해당 문서의 완료 기준에 체크하고 구현 기록을 남긴다.

문서 사이의 계약이 달라져야 한다면 관련 문서를 함께 수정한다. 사용자 요구사항과 문서가 충돌하면 사용자 지시를 우선한다.

## 공통 완료 원칙

- 화면에 버튼이 있는 것만으로 기능을 완료 처리하지 않는다. 저장·실패·재시도까지 확인한다.
- SQL은 지원 범위 안에서 의미가 보존되어야 한다. SQL 문자열의 공백과 정렬이 같은지는 핵심 기준이 아니다.
- 미지원 기능을 조용히 삭제하거나 다른 DBMS 구문으로 추측 변환하지 않는다.
- 새 SQL dialect를 위해 공통 편집기·프로젝트 API에 DBMS별 분기문을 계속 추가하는 구조를 만들지 않는다.
- 문서 형식 버전, SQL 엔진 버전, 서버 저장 리비전은 서로 다른 값으로 관리한다.
- 7단계의 배포 준비는 패키징과 로컬·테스트 환경 검증까지다. 실제 외부 배포는 그 시점의 사용자 요청 범위에 따른다.
