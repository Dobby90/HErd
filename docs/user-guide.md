# 사용 가이드

## 편집과 저장

자체 계정이 활성화된 서버에서는 **계정 만들기**로 가입합니다. 로그인 직후 **내가 만든 프로젝트**가 먼저 표시되고, 다른 사람이 공유한 프로젝트는 아래에 표시됩니다. **새 프로젝트**로 프로젝트를 추가합니다. 프로젝트를 열면 저장된 ERD의 첫 번째 뷰가 목록에 미리보기로 표시됩니다. **로컬 편집기**에서 브라우저에 저장하는 편집기를 열 수 있습니다. 상단의 달·해 버튼으로 라이트·다크 모드를 전환할 수 있고, 선택은 브라우저에 저장됩니다.

**프로젝트**에서 로그인하고 프로젝트와 ERD를 만듭니다. 새 ERD를 만들 때 PostgreSQL 17을 선택합니다. 왼쪽 스키마 탐색에서 네임스페이스와 테이블을 추가합니다. 테이블을 선택하면 오른쪽 속성 패널에 **컬럼**이 먼저 표시됩니다. **제약**과 **인덱스**에서 키와 인덱스를 편집하고 **설정**에서 물리명·논리명과 뷰 배치를 편집합니다. 같은 테이블을 여러 뷰에 배치할 수 있습니다. **이 뷰에서 숨기기**는 배치를 제거하고, **스키마에서 실제 삭제**는 관계와 뷰에 미치는 영향이 표시되는 확인 창을 엽니다.

FK를 추가하려면 컬럼의 오른쪽 핸들을 참조 대상 컬럼의 왼쪽 핸들로 드래그하거나 속성 패널의 **제약 → 외래 키 추가**를 사용합니다. 복합 키는 부모 키의 각 컬럼에 다른 자식 컬럼을 대응시킵니다. **논리 관계**는 다이어그램에서 표기할 관계를 정의합니다. **스키마 및 뷰 검색**에서 이름을 검색하고 일치 항목을 선택하면 배치된 테이블로 이동합니다. **그리드 정렬**은 현재 뷰의 테이블을 이름순으로 배치하며 실행 취소로 되돌릴 수 있습니다. 뷰 이름 옆의 **뷰 설정**에서 이름을 바꾸거나 뷰를 복제·삭제합니다. 캔버스 아래의 **미니맵**을 열어 넓은 도면에서 위치를 확인하고 이동할 수 있습니다. 작은 화면에서는 상단의 **다이어그램**, **스키마**, **속성** 버튼으로 편집 영역을 전환합니다.

서버 문서는 편집 후 약 1초 뒤 자동 저장합니다. 저장 상태와 리비전은 편집기 상단에서 확인합니다. 문서 제목 옆 연필 버튼을 누르면 제목을 바꿀 수 있습니다. 충돌하면 **서버 최신본 확인**, **내 변경을 새 문서로 복제**, **변경 폐기 후 다시 열기** 중 하나를 선택합니다. 오프라인이나 로그인 만료 뒤에는 같은 계정으로 접속하고 **브라우저 복구본**에서 편집하던 상태를 엽니다.

## 캔버스에서 편집하기

- 캔버스 상단의 **+ 테이블**을 캔버스로 끌어 놓거나, 버튼을 누른 뒤 빈 위치를 클릭합니다. 이름을 적용하면 첫 컬럼 입력이 열립니다. 왼쪽 스키마에서 기존 테이블을 끌어 현재 뷰에 놓을 수도 있습니다.
- 테이블 이름, 컬럼 이름, 자료형은 더블클릭해 수정합니다. 선택한 테이블 하단의 **컬럼 추가**에서 이름, 자료형, NULL 허용을 입력합니다. 테이블에 기본키가 없으면 컬럼을 기본키로 지정할 수 있습니다. `Tab`으로 필드를 이동하고 `Enter`로 적용하며 `Esc`로 취소합니다.
- 선택한 테이블의 컬럼 그립을 끌어 순서를 바꿉니다. 키보드로는 그립에서 `Alt+↑` 또는 `Alt+↓`를 누릅니다. 복합 키, 인덱스, DEFAULT·CHECK 식은 테이블의 **속성**에서 편집합니다.
- **관계 연결 → 식별 FK / 비식별 FK**를 선택하고 부모와 자식 테이블을 차례로 클릭합니다. 후보키의 컬럼마다 새 자식 컬럼을 만들거나 기존 컬럼에 매핑합니다. 자식 기본키에 모든 FK 컬럼이 포함되면 식별 FK(실선), 그 외에는 비식별 FK(파선)로 표시합니다. 컬럼 연결점 드래그와 관계선 더블클릭으로도 FK 설정을 열 수 있습니다.
- **관계 연결 → 논리 관계**에서 출발·도착 테이블과 1:1, 1:N, N:M 중 차수를 지정합니다. 논리 관계는 점선으로 표시하며 DDL에 FK 제약을 생성하지 않습니다.

## PostgreSQL DDL

- 프로젝트 화면의 **가져오기 → DDL로 새 ERD 만들기**에서 SQL을 붙여 넣거나 UTF-8 `.sql` 파일을 올립니다. 기본 스키마를 정하고 **DDL 분석**을 실행합니다. 제외 항목이 있으면 누락되는 내용을 읽고 해당 분석의 확인란을 선택한 뒤 적용합니다. 문법 오류와 남은 모델의 미해결 참조는 입력을 수정해 다시 분석합니다.
- 서버 ERD 편집기의 **가져오기 → DDL로 테이블 추가**는 기존 모델과 배치를 유지하면서 현재 뷰에 새 테이블을 배치합니다. 새 테이블의 외래 키는 기존 테이블을 참조할 수 있습니다. 같은 이름의 테이블이나 기존 객체를 변경하는 DDL은 분석에서 오류로 표시됩니다.
- 서버 ERD 편집기의 **가져오기 → DDL로 모델 교체**는 저장된 문서의 모델과 뷰를 바꿉니다. 테이블 추가와 모델 교체 모두 서버 리비전을 확인한 뒤 적용하며, 적용 전 버전은 **버전 이력**에 보존됩니다.
- 상단의 **내보내기 → DDL 내보내기**에서 전체, 현재 뷰 또는 선택한 테이블을 고릅니다. 부분 생성은 의존성을 확인한 뒤 SQL 생성으로 진행합니다. 성공 결과의 원본 리비전을 확인하고 복사하거나 UTF-8 `.sql`을 다운로드합니다. [지원 구문과 덤프 형식](sql-support/postgresql.md)

## 공유와 버전 이력

공유할 사람은 로그인한 프로젝트 목록에서 **내 공유 코드**를 확인합니다. owner는 프로젝트의 **멤버 관리**에서 코드를 입력해 사용자를 확인하고 역할을 선택합니다. Owner는 멤버를 관리하고, editor는 문서를 편집하고 복원할 수 있으며, viewer는 문서를 열고 SQL과 이미지로 출력할 수 있습니다.

**버전 이력**에서 저장 가능한 현재 리비전과 복원할 수 있는 스냅샷을 봅니다. **수동 스냅샷 저장**에는 설명을 붙일 수 있습니다. **과거 버전 열기**는 읽기 전용 도면을 보여줍니다. **이 버전으로 복원**을 확인하면 현재 상태를 보존하고 선택한 상태를 새 리비전에 저장합니다.

## 이미지 출력

상단의 **내보내기 → 이미지 내보내기**에서 현재 뷰 전체 또는 선택한 테이블을 고릅니다. 물리명·논리명, 컬럼 표시, 그룹·메모, 배경, PNG 배율을 지정하고 **출력 미리보기**로 실제 범위를 확인한 뒤 PNG 또는 SVG 파일을 다운로드합니다. 범위 밖으로 이어지는 관계선은 미리보기에서 제외됩니다. PNG 크기 한도에 걸리면 배율을 낮추거나 작은 뷰를 선택해 다시 출력합니다.
